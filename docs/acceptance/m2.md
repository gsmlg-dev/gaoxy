## Bounded implementation and open work

The native profile implements HTTP/1.1 and explicit HTTP/1.0 persistence over
TCP or OTP TLS. It rejects H2 ALPN; no H2 decoder exists. Request headers,
bodies, trailers, per-write chunks, WebSocket frames/messages, callbacks and
request lifetimes have configured finite limits. Admission charges retained
request framing, selected output windows and WebSocket state. Kernel/OTP socket
buffers and arbitrary trusted application allocations are outside that ledger;
neither the tests nor this record establish a bound on total BEAM memory.
See [the limits and unsupported features](../native-http.md).

The historical HTTP Fetch 0.17.1 H1 probe returned decoded gzip bytes with the
original encoding/length headers, discarded trailers and timed out instead of
delivering an early 413. Source inspection found no public 101 upgrade tunnel.
The unchanged-source reproduction is in integration/http_fetch_contract/.
Upstream issues are [#27 raw bytes](https://github.com/gsmlg-dev/http_fetch/issues/27),
[#28 early response](https://github.com/gsmlg-dev/http_fetch/issues/28),
[#29 trailers](https://github.com/gsmlg-dev/http_fetch/issues/29) and
[#30 upgrade tunnel](https://github.com/gsmlg-dev/http_fetch/issues/30).
All four issues were still OPEN at the 2026-10-09 09:19:16 UTC
[refresh](evidence/m2/upstream-issues.json).
Those four issues are CLOSED as of the 2026-10-10 revalidation. The selected
published packages are now 0.17.2. Five public-API contract tests passed with
zero failures: buffered and ACK-streamed raw gzip/duplicate headers, ordered
response trailers, early 413 with upload termination, declared upload trailers,
and WebSocket upgrade/initial-frame preservation, ACK writes and normal cleanup.
Strict umbrella compilation also passed. These validate dependency contracts,
not an implemented Gaoxy proxy.

Two public-API probes remain failed gates (each exits 1):

- [Method-body probe](../../integration/http_fetch_contract/method_body_probe.exs):
  POST preserves `abc` and Content-Length 3; GET/DELETE discard the body and
  remove Content-Length. New upstream Bug #45 records this blocker.
- [WebSocket close probe](../../integration/http_fetch_contract/websocket_close_probe.exs):
  1000 returns `:ok`; valid 1001, 1008 and 1011 return
  `{:error, :invalid_close_code}`. The valid-close-code portion of open #38
  blocks M2 WebSocket proxy semantics. Exact fragmentation and ping/pong
  forwarding are not M2 requirements.

The client still has a global streaming threshold. A future proxy may require
explicit static startup `streaming_threshold: 0`, validated at initialization;
it must never mutate the threshold per request. Under this host constraint,
[#37](https://github.com/gsmlg-dev/http_fetch/issues/37) is not an M2 blocker.
The proxy package now transitively installs `elixir_quic` and `ex_ssl`; core-only
consumer isolation does not describe the umbrella graph or imply H2/H3 support.
Resume blocked proxy work after #45 and valid-close-code support in #38 are fixed
and the published dependency is updated. No local workaround or placeholder API
is counted as delivery.

No push, merge, release, deployment or hosted M2 run is part of this local
acceptance record. Local commits do not establish publication or full M2
