## Bounded implementation and open work

Native HTTP/1.1 and explicit HTTP/1.0 persistence use TCP or OTP TLS. Request and
WebSocket lifetimes, callbacks, framing and retained payloads have finite limits.
The WebSocket proxy reserves upstream capacity before activation; one data delivery
per direction is outstanding, acknowledgments follow local writes, and no uncertain
write is replayed. Session guardians are outside the per-instance force-kill tree.
Their receipt follows public upstream socket PID termination; unexpected guardian
death fails service admission closed. Deadline expiry never becomes successful
cleanup merely because a caller stopped waiting.

These are payload/admission bounds, not total BEAM or kernel memory claims. Trusted
application allocations, OTP/kernel socket buffers and process overhead are outside
the ledger. See [native limits](../native-http.md) and
[WebSocket proxy configuration/accounting](../websocket-proxy.md).

Historical 0.17.x/0.18.1/0.19.0 dependency failures remain documented in their
separate bundles. HTTP Fetch 0.19.1 resolves both completion and empty-query
contracts. The public reproduction and full proxy wire test now pass without
an upstream workaround. Remaining H2/H3 and complete gateway work is outside M2.

No push, merge, release, deployment or hosted M2 run is part of this local record.
