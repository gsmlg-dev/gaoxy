## Membership defect and authorized recovery (historical boundary)

`evidence/membership-probe.log` records an actual macOS IPv4 multicast endpoint
started through Gaoxy and an absent-leave operation through `Gaoxy.leave/3`.
The command exited 1: `KeyError key :id not found`, at
`apps/gaoxy/lib/gaoxy/service.ex:108`.
`put_in(state.spec.udp[:memberships], value)` returns the updated outer service
state, but the next line treats it as the specification (`spec.id`). A successful
backend operation therefore crashes the service before its desired-state update.
The handoff must preserve the completed two-round runtime repair counter; this
new symptom does not create a new repair budget. The user has now authorized
bounded Astra recovery with at most two repair-and-validation rounds. Root has
stopped runtime writes and transferred exclusive runtime/test ownership to that
worker; prior logs and Sol's two-round counter remain preserved.

Astra rooted the update at `state.spec` and verified actual public absent leave,
duplicate join/leave, membership limit, retained identity and desired-state
recovery after restart, including stale-generation rejection. First UDP admission
was measured at 198.55ms after backend receive credit was ready, explaining the
old 100ms test assertion failure; tests now wait on actual admitted-worker events
within the existing finite 2-second readiness budget. Runtime watchdog/drain
deadlines and overload bounds are unchanged.

Bounded recovery was accepted after root reviewed the two-file diff and actual
command evidence. Counters remain Sol=2, Astra=1; round 1's initial full TLS
timeout remains FAIL, with subsequent same-source validation PASS and no round 2
started. All commands finished, Astra stopped writing, and ownership returned to
root. At that recovery boundary full M1 acceptance was incomplete. Linux gates, external consumer and
production release were not rerun as part of Astra recovery; earlier evidence
retains its original scope. See `evidence/astra-runtime-handoff.log` for exits,
