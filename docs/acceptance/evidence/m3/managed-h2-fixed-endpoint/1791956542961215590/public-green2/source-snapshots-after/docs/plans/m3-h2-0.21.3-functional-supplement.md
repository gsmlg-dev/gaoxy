**Goal:** Qualify the released #98 H2 parser-error retention and #100 untracked

peer: exactly eight cases, four verified TLS H2 and four h2c.

**Design:** Use a separate finite Elixir controller and a small Python peer with
public `h2` request decoding and two fixed raw response frames. Each case owns
one fresh loopback listener, one connection, one GET, and its peer process.
Supported request completion is asserted only for manual-redirect parser cases.
Default-follow cancellation cases explicitly assert unsupported completion and
use wire/reader/owned-process observations without claiming request cleanup.

mutation, private ConnectionOwner/Pool/RequestLifecycle calls, managed scope,
generation retirement, or production upstream-transport Tasks4–8. This slice
does not establish sibling isolation, the four-way proxy matrix, adversarial

## 2. Frozen caller profile and public semantics

All cases use `HTTP.fetch/2` with the following explicit base options:

```elixir
[
  method: :get,
  request_mode: :fetch,
  body: nil,
  stream_response: true,
  decode_body: false,
  error_mode: :raw,
  http2_profile: :native_v1,
  http2_reuse: true,
  http2_scope: unique_case_scope,
  tls_backend: :ssl,
  timeout: 6_000,
  connect_timeout: 2_000,
  telemetry: false,
  socket_opts: [send_timeout: 2_000, send_timeout_close: true]
]
```

`unique_case_scope` is a finite binary containing this invocation's unique ID and
one registered case ID; it is not reused by another case. Leave the native wire
profile settings and ordinary pool implementation unchanged. No custom pool,
priority, upload, proxy, Unix socket, structured error, or transport scope.
`HTTP.Config.streaming_timeout/0` must equal the source default60,000ms; record
the observed value and fail the fixture prerequisite if configuration overrides
it. Do not change global application configuration to make the test pass.

- h2c: `http_version: :h2c`, URL `http://127.0.0.1:<port>/target`.
- TLS: `http_version: :http2`, URL `https://127.0.0.1:<port>/target`,
  `ssl: [cacertfile: peer_ca, verify: :verify_peer]`.
- #98 parser cases: add `redirect: :manual`; obtain the original completion
  exactly once with `HTTP.Promise.completion/1`.
- #100 cancellation cases: add `redirect: :follow`, the documented default,
  and `signal: controller`, where `controller = HTTP.AbortController.new()`.
  Assert `RequestCompletion.await(Promise.completion(promise), 0)` returns
  exactly `{:error, {:unsupported_completion, :redirect}}`. Do not call
  `abort_and_await/2` on that handle or interpret it as cleanup evidence.

`request_mode: :fetch` is the default body grammar; it does not choose tracking.
The manual/follow redirect choice chooses supported/unsupported completion even
for status200 responses without Location. All cases omit `connect_address`:
FetchOptions forbids it with follow. Literal loopback URLs remove DNS ambiguity.
The new TLS certificate must contain `subjectAltName=IP:127.0.0.1`, with valid
serverAuth and disposable CA signing; verify it with OpenSSL `-verify_ip
127.0.0.1` before readiness. Preserve OTP's default hostname verification and
require peer ALPN `h2`; never use verify_none or a permissive verify callback.

## 3. Independent peer grammar

Use pinned `integration/h2_gateway/requirements.txt`: h2 4.3.0, hpack 4.1.0,
hyperframe 6.1.0. Record actual versions and executable identity; reject mismatch.
One peer invocation accepts `--protocol tls` or `--protocol h2c`, binds only
127.0.0.1 on an ephemeral port, and rejects a second connection or request.
An acceptor and one socket worker are owned and joined. Ready output includes
protocol, port, trust-file path when applicable, and package versions.

Python decodes the HTTP/2 preface and request using public h2. Require exactly
one GET `/target`, authority `127.0.0.1:<port>`, appropriate scheme, and request
END_STREAM with zero upload bytes. Perform ordinary SETTINGS/ACK exchange and
send status200 HEADERS without END_STREAM. No Content-Length, Location, trailers
or DATA are sent automatically. Record the accepted connection ID and stream ID.

The JSON control pipe exposes exactly these commands:

| Command | Action and receipt |
|---|---|
| `reader_sentinel` | Once, only in an early-reader case: send one DATA byte `r`, flags0; record the actual frame bytes/stream and successful send. |
| `malformed_trailers` | Once, only in a parser case: send raw HEADERS type1, flags4 (END_HEADERS, no END_STREAM), target stream, payload `00 01 78 01 76` (literal `x: v` without indexing). Record exact serialized hex and successful send. |
| `stop` | Stop accepting, shutdown/close all owned sockets and listener, join worker and acceptor, delete disposable trust files, emit `stopped` with live_threads0, exit0. |

Do not pass malformed trailers through h2's validated header sender. Raw bytes
deliberately test a nonterminal trailer block; payload is five bytes and wire
frame fourteen bytes. h2 remains the independent decoder of client responses.
Enforce at most3 control commands per case (including cleanup `stop`),
at most128 emitted event lines per case, and at most4096 bytes per encoded
control/event line. Read at most4097 bytes; reject oversized or nonterminated
input, duplicate and unknown commands. Cleanup consumes these same finite caps.
These are fixture bounds, not upstream memory/accounting proof.

Record received RST_STREAM ID and numeric code; require code1(PROTOCOL_ERROR)
for malformed trailers and code8(CANCEL) for abort/deadline. Record any unexpected
request, DATA, reset, GOAWAY, worker exception or connection closure; none may be
silently swallowed or counted as a successful expected reset.

## 4. Registered cases and exact public oracles

| Case ID | Protocol | Reader placement | Exact stream error |
|---|---|---|---|
| TLS98_LATE | verified TLS H2 | first read after malformed reset | `:invalid_headers_transition` |
| TLS98_EARLY | verified TLS H2 | sentinel consumed/ACKed before malformed send | `:invalid_headers_transition` |
| TLS100_ABORT | verified TLS H2 | first read after abort reset | `:aborted` |
| TLS100_DEADLINE | verified TLS H2 | first read after original deadline reset | `:request_timeout` |
| H2C98_LATE | h2c | first read after malformed reset | `:invalid_headers_transition` |
| H2C98_EARLY | h2c | sentinel consumed/ACKed before malformed send | `:invalid_headers_transition` |
| H2C100_ABORT | h2c | first read after abort reset | `:aborted` |
| H2C100_DEADLINE | h2c | first read after original deadline reset | `:request_timeout` |

Every case first requires `%HTTP.Response{status: 200, http_version: :http2,
body: stream}` from a finite `HTTP.Promise.await/2`. Monitor that exposed stream
before any terminal action. Match receipts to this case's port/connection/stream;
another case's event or a mere successful send cannot satisfy a reset barrier.

**#98 late sequence:** Await response without sending any read message. Release
malformed trailers; await independent code1 reset. Before first read, require
`{:error, :cleanup_pending} = RequestCompletion.await(original_completion, 0)`.
Then send `{:read_chunk, self(), :ack}` to the response stream. Require exactly
`{:stream_error, stream, :invalid_headers_transition}`, normal stream DOWN, then
`:ok` from the original completion with a bounded remaining-time wait. Also
require a repeated zero-time original completion wait returns `:ok`.

**#98 early sequence:** Await response; send the public acknowledged read message
and release `reader_sentinel`. Receipt of exactly
`{:stream_chunk, stream, "r", ref}` proves the reader has attached; send
`{:stream_chunk_ack, ref}` before releasing malformed trailers. Require code1
reset, the exact parser error, normal stream DOWN and original completion `:ok`,
including the repeated zero-time wait. No second read registration is sent.
The sentinel makes early placement deterministic without inspecting stream state.

**#100 abort sequence:** With follow completion already verified unsupported,
await response but do not read. Call `HTTP.AbortController.abort(controller)` once
and require `:ok`; wait for code8 reset before the first read. Require exactly
`{:stream_error, stream, :aborted}` and normal stream DOWN.

**#100 deadline sequence:** Follow completion is unsupported; await response and
do not read or abort the controller. Hold the peer response open until the
original6,000ms request timeout produces code8 reset. Only then register the first
reader; require exactly `{:stream_error, stream, :request_timeout}` and normal
stream DOWN. Do not restart Fetch, replace its timeout, or use a fresh request.

Late placement here means the first reader follows the peer-observed reset; it
does not assert private error-mailbox state at that instant. This matches the
released upstream regression's public/wire ordering. An error can arrive during
reader registration and still must preserve the original reason.

After normal stream DOWN, scan the case mailbox for that stream: exactly one
terminal error in total, no other error, stream_end, trailers, or unexpected
chunks. Only early cases receive the one sentinel byte. Stream DOWN followed by
the mailbox check bounds the observation; no arbitrary sleep is an oracle.
Each case requires exactly one accepted connection and one target request, no
replay, exactly one expected reset, successful owned shutdown and exit0.

## 5. Immutable deadlines and owned cleanup

Parent wraps the complete invocation in one600-second external collector
deadline: eight*(45-second ready +15-second case) is at most480 seconds,
with bounded startup/reporting headroom. Preserve the actual child wait/exit
result before parsing. On timeout, shut down only the recorded owned process
group, join it within finite termination waits, record partial evidence and FAIL.
Do not renew the per-case D/C deadlines or reinterpret timeout as PASS.

Capture each absolute deadline once; every adaptive wait uses its remaining
time, never `now + original_duration` again. Record deadlines, operation start,
result and actual elapsed time separately from the request's configured timeout.
Define `remaining(deadline) = max(deadline - monotonic_now_ms, 0)`; zero remaining
time fails an unfinished operation immediately. In the formulas below, `D-now`
always means this nonnegative remaining value, and cleanup uses remaining C.

- Peer creation: ready deadline `peer_start + 45_000ms`; each of four OpenSSL
  commands is capped at10,000ms. TLS handshake2,000ms; socket polls100ms.
- After ready, set `t0` immediately before Fetch. Oracle deadline `D=t0+10_000ms`
  and cleanup deadline `C=t0+15_000ms` are both fixed at this point. Request
  timeout6,000ms, connect/send timeouts2,000ms remain unchanged. The dependency
  initializes its internal request clock asynchronously; D is a separate outer
  observation ceiling and is not claimed to be its exact internal deadline.
- Promise, sentinel, parser/reset and terminal waits use `min(2_000, D-now)`;
  the deadline-case reset uses all remaining D because the original request
  clock must expire. Never accept :timeout, closed, aborted or stream_reset as
  substitutes for the exact registered reason.
- Completion after consumption uses `min(2_000, D-now)`; zero-time checks stay0.
- Success teardown starts before C: stop owned AbortController agents using
  finite `Agent.stop/3` and require their normal DOWN; send peer stop, require
  live_threads0 and its port exit0 before C. Peer joins use one shared2,000ms
  shutdown deadline, not an independently renewed budget per thread.

Every acquisition records its cleanup responsibility immediately, including
partially started peers, response stream monitors and controllers. Never discover
or stop unrelated processes. All exit paths enter the same owned cleanup block.
On failure, a supported parser completion may be aborted and awaited within C;
for follow requests use public AbortController.abort/1 and register/drain the
exposed reader if needed. This cleanup cannot replace the failed original oracle
or create PASS. Close the owned peer's stdin on startup/command failure; its EOF
finally block must run the same finite socket/thread/tempfile shutdown. If normal
shutdown fails, terminate only the recorded owned peer PID/process descendants
and exposed case-owned stream/controller, record forced cleanup and FAIL. Preserve
the original failure even if cleanup subsequently succeeds. If safe ownership or
shutdown cannot be confirmed, report BLOCKED_HANDOFF and do not start another case.

For untracked cases, response stream normal DOWN plus peer reset/socket shutdown
and controller shutdown are scoped observations only. Unsupported completion
provides no request-resource barrier or native reclamation receipt. Successful
suite execution ends its dedicated BEAM invocation; do not extrapolate to a
long-lived shared-pool cleanup/accounting claim.
