# Managed H2 groups and probes implementation plan — draft

> For agentic workers: execute bounded tests-first tasks with explicit ownership and independent SPEC then CODE review. Parent chooses and coordinates parallel source-only workers; parent alone owns repository integration, Mix/build/runtime/format/peer/browser commands and commits. The current assignment produces drafts only and starts none of these tasks.

**Goal:** Activate immutable managed H2-family upstream groups and bounded HEAD health probes with unchanged H1 compatibility and original-completion cleanup.

**Architecture:** Reuse the group owner and physical managed transport scopes. An explicit H2 handle profile selects bounded preselection admission, followed by exactly one selected-member H2 envelope. Probe and Session share the accepted ManagedH2Client and public original completion APIs.

**Tech stack:** Existing Gaoxy umbrella, Elixir/OTP SSL, pinned HTTP cohort 0.21.10, Python h2 4.3.0/hpack 4.1.0/hyperframe 6.1.0 independent peer, existing isolated browser fixture. No new dependency/process architecture.

**Canonical Mix command prefix:** every Mix command below runs from the selected worktree as `nix develop --command env 'ERL_FLAGS=+S 2:2' MIX_ENV=test unbuffer mix ...`. The quoted environment assignment is one argv value. Network Python entrypoints run under the same Nix/runtime environment as `nix develop --command env 'ERL_FLAGS=+S 2:2' MIX_ENV=test python ...`; new runner Mix child argv uses the Mix prefix including unbuffer. Existing predecessor runners retain their qualified child command and identity contract. No bare system Mix invocation is authorized by these snippets.

Design authority: companion `gaoxy-h2-groups-probes-design-draft.md`, D1–D6/GP01–GP11. Intended adopted paths after entry: `docs/designs/m3-managed-h2-groups-probes.md` and `docs/plans/m3-managed-h2-groups-probes.md`.
