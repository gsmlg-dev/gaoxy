At startup, the four Q roots are a conservative simultaneously live bundle, not four aliases: caller/start argument, supervisor-transferred call/MFA, child-transferred init argument, and child returned state. A group endpoint/handle is a separately bounded H root rather than a fixed HTTP C. `Session.init` uses `Map.merge(args, ...)`; local `args.request_options` extraction does not become a fifth Q.

The group checkout wire request has zero Q/C/K payload: `{:checkout, handle, pins, guardian, %{}, deadline}`. The reply introduces a selected `member.config`: sender reply and receiver copy must be charged during transfer; sender `member.config` projection inside that reply is not another C. Group owner old/new member maps remain separately accounted owner roots. Similarly transport checkout returns a complete checked client; its policy and fetch_options projections are already inside its K.

A four-K *candidate envelope* can allocate sender checked reply, receiver Session client, opening options client, and bounded validation projection. It is conditional on no additional retained old state/client sidecar. It is not a measured maximum. `ManagedH2Preparation.canonical_policy/1` validates existing policy and returns `:ok`; it does not itself return another complete checked client. Synthetic validation policy in request_shape is finite scratch, not a second copy of trust-bearing checked policy.

For Q, `ManagedH2Client.open_prepared` builds a seven-key source, obtains a complete `{:ok, request, accounting}`, assembles source Fetch arguments and calls public Fetch. `envelope = options.request` is an alias; fields/url extracted from complete request are projections. The full preparer return is charged once, including manifest. Public Fetch builds options/request/managed request and launches its dependency task; those independent dependency representations need their established upstream ledger/boundary, and cannot be used as unexplained proxy slack.

## Required release boundaries

1. After startup acknowledgement and start_child return: no supervisor retained MFA args for temporary child; do not count persistent supervisor Q/C. Caller/start args are dead only when no continuation still retains them.
2. After group checkout: transfer/consume exactly the selected reply; never retain full member or reply alongside an extra selected-config sidecar. Count sender and receiver transfer roots during the boundary.
3. At handoff resume: clear awaiting_transport in the new state before checkout/open; charge old waiting state until callback transition ends. Handoff notification must carry only bounded identity and pins, never C/K/Q.
4. After selected-envelope assembly, BEFORE ManagedH2Client.open/Fetch: remove Neutral and selected full config from new live opening state/continuation where not needed; retain only envelope plus finite limits/control, selection tokens, pins and URL provenance. Clearing only after successful bind does not establish this pre-open boundary.
5. At prepare return: retain one complete request/accounting return, never charge request projection/accounting projection a second time. Release source/assembly scratch before using their slots for Fetch source arguments.
6. At Fetch return: discard complete preparation/accounting and source Fetch options; retain only validated handle/upload and required submitted_url. Do not retain a checked client in handle or extra sidecar.
7. After successful completion binding: clear request_options, managed_transport, selector, awaiting_transport, transport_handoff, and full fixed-config payload fields. Explicitly define group residual URL extraction because Neutral has no url.
8. On all opening, preparation, bind, cancellation, deadline and cleanup-unconfirmed paths: drop source/config/K when no longer needed without discarding original completion, cleanup identity, pins or tokens; failure paths require their own phase proof.
