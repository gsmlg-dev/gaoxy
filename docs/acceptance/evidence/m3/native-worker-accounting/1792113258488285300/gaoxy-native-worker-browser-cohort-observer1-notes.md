## Exact API

- `install(gate, %{service: service_pid, mode: :h1 | :h2}) -> {:ok, observer}`. Install caller becomes owner; start observer unlinked, set private OTP27+ trace session VM filters, install only its own Gate sys debug hook before Chrome. Root must monitor observer immediately. Owner must handle `{:cohort_observer_fault, observer, finite_atom}` and genuine observer DOWN as FAIL. Other init/assertion failures are real observer crashes, not swallowed successes. API currently supports actual proper initialized service PID, not service ID or mode strings.
- `native_start(observer, self(), %{service: service_pid, listener: listener_span_ref, acceptor: acceptor_span_ref, span: connection_span_ref}) -> :ok`. Call synchronously inside the root-filtered TI connection :start callback before handshake. Observer installs an actual monitor before acknowledging. Root must have attached listener/acceptor telemetry before service add, prove exact single native listener/public listen_port and ancestry in its ETS, and pass ONLY verified ancestry. Helper verifies PID caller/service identity and primitive span refs; it does not guess local_port from connection metadata or independently validate the external ancestry table. Observer hot-path handlers never call/wait on Gate/service, so this handshake has no reverse dependency. Failure/timeouts remain FAIL.
- `snapshot(observer, gate) -> %{status, leases, spawns, cleanups, bytes, sequence, from, ledger}`. CALLER first registers as an expected snapshot caller, then issues actual public `:gen_server.send_request(gate, :status)` and `receive_response`. This is the public GenServer form of Admission.status with explicit finite-alias request identity, not a new product API. Returned `from` is the exact `{caller, [:alias | request_id]}` wire envelope; response status must equal the matching Gate out-State's status exactly. One absolute2s deadline covers caller registration/public response/snapshot receipt; no later independent Gate-state query. A100ms GenServer-call delivery allowance does not permit success past deadline because finalization checks remaining absolute time. Private trace-delivery marker and actual writer-ready observations must complete before snapshot reply.
- `facts(observer) -> ledger`. Failure-path currently processed finite prefix only; it is NOT a flush, join, completeness or runtime acceptance proof. It never calls Gate.
- `stop(observer, gate) -> :ok`. Removes ONLY stable own hook `{NativeWorkerBrowserCohort, observer}` and normally stops observer/destroys ONLY own trace session. Root must monitor and receive actual observer normal DOWN, and call this before Gate/service stop. If observer already crashed, root can remove exactly that known hook itself and use the genuine crash receipt; do not infer normal observer shutdown. No others' tracing/hooks/processes touched.

## Snapshot/ledger fields

All Gate projection record maps retain their complete current source key sets. Unknown field/unsafe value/oversized map fails explicitly rather than silently dropping it. Leases include all10 source fields (pid/monitor/bytes/token/timer/send/drain_notify/request_active/cleanup/deadline); pending send only operation ref and integer bytes. Spawn maps include all10 correlation fields (owner/parent_lease/worker/lease/activation/from/deadline/phase/exit_seen/down_seen); no MFA or spawn arguments. Cleanups include monitor/bytes/lease/receipt. Status contains all7 current Gate aggregate fields. Reference keys and primitive values are checked; no socket/native state/payload/TLS/stacktrace term is copied.

`ledger` has:

- `acquisitions`: `%{lease, pid, bytes, options, monitor, from, sequence}` for actual ordinary acquire successes. Exact From correlates original requested bytes/options with genuine returned lease and same-State PID/bytes/monitor. Options are exact[] or one boolean drain_notify keyword. A rejected acquire fails qualification explicitly, never supplies a made-up role/ref.
- `ready`: `%{writer, owner, timestamp, delivery}` from VM-filtered genuine W->C writer_ready, sender===embedded writer PID, owner is actual destination PID. Duplicate ready fails. `delivery` distinguishes send and send_to_non_existing_process; root must decide permitted delivery with actor lifecycle, never infer a live owner.
- `native_starts`: `%{pid, service, listener, acceptor, span, monitor}` from acknowledged pre-handshake registration.
- `terminal`: `%{pid, monitor, reason, source, sequence}`; authenticated Gate-monitor entries additionally carry lease ref, source `:authenticated_gate_monitor`, and exact Gate debug sequence. These match monitor+PID obtained from actual successful ordinary acquisition; Gate consumes that DOWN synchronously before any later status call. Root derives ordinary refs at a past cut from acquired.sequence<cut.sequence minus these genuine DOWN sequences<cut.sequence. Do not intersect arbitrary present keys and call that expected set. Spawn-child and cleanup-guardian terminals remain root's strict existing responsibility, not ordinary-acquire removals.
- Observer-monitor terminal source is `:observer_monitor`, sequence:nil. Native actor monitors are pre-handshake; writer observer monitor may be late and yield :noproc, which is expressly NOT normal-exit proof. Its authenticated Gate-monitor terminal remains the genuine ordinary writer lifetime receipt. Do not use sequence:nil to rewrite any past cut.
- `causal`: safe directional scalar events for actual h2_written result, stop send/receive and owner DOWN receive, with actual traced pid and monotonic timestamp; sender/destination, operation token/monitor/owner refs included only where emitted. Each is also sent to owner as `{:cohort_trace, observer, projected_fact}` for safe append/failure diagnosis. Root must handle these messages in every relevant receive/drain path, without classifying them as unexpected host messages. A scalar write error/received stop/received owner DOWN can distinguish original source writer return branches; no prior failure is reclassified absent actual evidence.

## Trace privacy and bounds

Private trace session send matchspec admits ONLY writer_ready where embedded sender===self, h2_written with real token and result :ok/:expired or {:error,atom}, and :stop to a PID. Receive matchspec admits ONLY :stop, DOWN with ref/PID/atom reason, or exact shutdown/peer_closed reason. Filters run in VM before delivery to the observer, so arbitrary sends/receives, raw sys replies, TLS/socket/state/payload and task arguments do not enter the tracer. No :procs, :call, inheritance or global legacy trace_pattern is enabled. Acquire :in enables this session's send/receive timestamps BEFORE acquire replies, preventing lost short-lived writer-ready/causal sends. Actor deaths use actual monitors rather than :procs tracing (which would expose spawn args).

Terminal projection uses finite atom list and at most3 shutdown/handshake/tls_alert wrappers; unknown terminal contents become an explicit sentinel, not an accepted normal reason. Root must fail unsupported terminal classification. User-injected arbitrary messages are outside this isolated source-owned fixture.

Finite bounds:90s observer lifetime;2s snapshot/native registration/setup calls;2048 retained observations;128 lifetime ordinary acquisition identities/actor monitors,128 concurrent cuts/waiters and128 Gate projected leases/spawns/cleanups per map. Overflow/crashes/timeouts are qualification failure. Only callers explicitly registered by snapshot create retained status cuts: ordinary Service/Gaoxy.status polling replies are discarded as non-checkpoints and do not consume cut/event budget. Caller registration precedes public request, while exact alias ref still binds final receipt; no byte-total matching. Snapshot awaits writer_ready only for actually present ordinary acquired non-native actors at that cut, excluding spawned target child. After ready association, trace.delivered barrier ensures already-emitted safe trace facts are processed before return. Later ledger events retain their own sequences; root must filter past-cut membership by sequence and keep final joins distinct.
