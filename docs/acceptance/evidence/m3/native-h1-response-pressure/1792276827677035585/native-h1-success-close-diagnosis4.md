## Plug and terminal distinctions

PlugAdapter send/chunk delegates to Response; its already_sent messages describe response commitment and never signal Session consumption (`apps/gaoxy_http/lib/gaoxy/plug_adapter.ex:5-43`). PlugEndpoint returns the Exchange from conn.adapter and flushes commitment messages (`http/plug_endpoint.ex:26-58`). Native Connection also flushes commitment messages, marking error paths close=true, then finishes once; after proxy end, response=:sent makes that finish idempotent (`http/connection.ex:210-284`). No direct upstream close is present in these native/Plug consumers.

Chunked native H1 has a different boundary: the terminal zero chunk and trailers are emitted only inside Response.finish during dispatch(:end), immediately before consumed (`http/http1/response.ex:60-74`). A bodyless native response can finish on headers (`36-54,231-247`); HEAD/204/205/304 therefore have an analogous possible early-close interval, but that is separate from the evidenced fixed-length repair candidate.

Critically, FramedResponse also represents length exhaustion as `{:fixed_stream,0}`, but its chunks write DATA with ended=false and its finish writes END_STREAM or trailers (`http/framed_response.ex:57-62,78-89`). HTTP2.Response delegates to it (`http/http2/response.ex:1-11`). A raw tuple predicate shared across transports is therefore incorrect.
