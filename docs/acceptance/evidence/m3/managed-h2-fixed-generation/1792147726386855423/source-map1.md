## Finding and smallest source change

The concrete production gate is `apps/gaoxy_proxy/lib/gaoxy/proxy/http.ex:242-246`: every `%HTTP{upstream_protocol: :h2c | :http2}` returns `{:error, :unsupported_generation_endpoint}`, including canonical prepared configurations that already pass `HTTP.init/1` and `ManagedH2Envelope.validate_config/1`.

Smallest proposed implementation: change only that H2 clause to accept the **complete existing closed configuration schema**, preserving its rejection error and the existing non-H2 fallback:

```elixir
def generation_validate(%__MODULE__{upstream_protocol: protocol} = config)
    when protocol in [:http2, :h2c] do
  case ManagedH2Envelope.validate_config(config) do
    :ok -> :ok
    _ -> {:error, :unsupported_generation_endpoint}
  end
end

def generation_validate(_), do: :ok
```

This is a proposed patch, not an edit. Do not replace the denial with unconditional `:ok`, remove the callback, call the live owner here, call `HTTP.init/1` from this compiled-bound guard, add fields to T4, or attach a protocol marker that pretends to prove liveness.

### What 'prepared' can and cannot mean in the pure guard

T4 is exactly `%{provider: UpstreamTransports, owner: pid, owner_epoch: ref, resource: ref}` (`upstream_transports.ex:1472-1473`). It intentionally contains **no policy, authority, protocol, scope, instance or live attestation**. Pure validation establishes the prepared configuration/handle **schema**, not authenticity or liveness. A fabricated but well-shaped T4 can pass pure shape validation; existing owner pin acquisition rejects it. A genuine prepared H1 T4 placed in a canonical H2 config can pass shape validation and baseline admission; existing owner authority checks reject it before derived-pin creation/checkout/Fetch. Do not promise those two live checks occur before all owner contact.

That distinction is an existing architecture fact, not a required new API or external blocker. The admitted capability is a configured fixed H2 route using an authenticated prepared owner resource; actual selection must still bind protocol/authority/instance through the established live checks. Preserving unsupported raw/unprepared cases means retaining rejection of nil/invalid T4 or malformed/unprepared HTTP config, not inventing a pure live-resource oracle.

## CAS and retirement sequence that must be exercised

Use one old prepared T and one new prepared T for each explicit protocol. Release preparer pins only after the corresponding Store baseline is established, or they intentionally keep the transport configured.

1. Capture genuine old snapshot/request T8 in the listener request and hold the real request before handoff. Snapshot must identify old Router generation and old T4; do not inject pins or replace Generation with a wrapper.
2. Activate a prepared new Router with CAS against old generation. Store acquires new baseline then atomically swaps router+baseline; it queues old baseline release (`generation.ex:517-529,608-612`). Baseline reconciliation retries failed release (`:572-580`). Failed candidate, stale CAS or timeout never silently substitutes current router; an acquired-but-expired new baseline is released.
3. With old baseline and old preparation pin gone, owner `close_unpinned/2` sets old `admission: :closed`, but waits any request pin or token before retiring (`upstream_transports.ex:1117-1137`). Ordinary `pin_many` now fails old resource with `:resource_admission_closed` (`:889-907`). **Delegation and checkout intentionally check active/unconfirmed/not retirement_requested but do not require admission=:open** (`:359-365,405-410`): the authentic pre-CAS request source can still derive its one old Session child after CAS. Adding admission=:open there would break the required race.
4. New listener request captures new Router/new T and opens only the new owner policy/scope. Old request must use original old T/policy/scope/peer, without lookup of replacement routes or fresh pin acquisition. Native pump remains source holder; Session remains distinct child holder and checkout guardian.
5. Retain original completion and child until public cleanup is confirmed. Owner `finish/2` refuses nil completion, abort-helper in flight, or pending original completion (`:445-456,1260-1269`). Session runs original cleanup, finishes transport, releases child T8, completes Service, and exits normal (`session.ex:1346-1367,1398-1418,1711-1739`). Pump awaits Session's actual normal DOWN (`http.ex:1118-1122`) before successful endpoint return; Generation then releases its source T8 (`generation.ex:308-345`). Last pin/token disappearing triggers resource retirement. Transport cleanup still requires actual custodian/transport/helper completion before record settlement (`upstream_transports.ex:1522-1547`; `custodian.ex:107-119,162-179`).
6. Do not confuse **per-resource retirement caused by generation baseline release** with explicit whole-owner `UpstreamTransports.retire/2`: the latter intentionally clears pins, stops new admission, requests graceful transport retirement, then may abort after its deadline (`upstream_transports.ex:1552-1581,1604-1634`). Store death releases its baseline; it does not itself call whole-owner retire (`generation.ex:585-605`). Instance death/explicit owner retirement are separate cancellation conditions.
