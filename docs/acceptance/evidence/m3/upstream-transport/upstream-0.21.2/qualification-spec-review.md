## Decisive95 observation missing from the existing driver

`common/1` checks that aggregate resources are equal before/after reuse, but
does not require a source-derived TLS registration inventory. `zero_connections`
checks aggregate zero after closing, and retirement awaits a durable receipt.
Those checks can pass when receiver/sender were never registered: equality and
zero alone cannot distinguish an omitted resource class from its termination.
The old installed `track_tls/2` only matches the three-element form; its catchall
returns ok. The candidate package source instead recognizes the restricted
legacy form and OTP28's **eight-element** form
`{:sslsocket, tcp, receiver, sender, :gen_tcp, _, _, _}`; it registers TCP plus
receiver and sender, hands those resources off at pooling, and marks unsupported
representations uncertain. No six-element representation is assumed.

Recommend a separate bounded public fixture specification, reviewed before its
implementation, with these concrete checks:

1. Bind installed, compiled/loaded candidate code and actual OTP28 profile.
   Derive the complete quiescent scope-resource inventory from source before
   runtime: expected HTTPS H1 is one TCP port plus receiver/sender (3); expected
   ALPN H2 additionally includes its persistent connection owner (4). Verify
   all temporary request/dial/upload/stream owners are gone at the observation
   boundary and independently review these exact counts. Never choose a count
   from samples or replace it with merely positive resources.
2. Use one persistent fixture custodian and one independent verified TLS peer,
   explicit `:http1` and separate `:http2` scopes, literal destination, one
   connection and finite request/idle deadlines. After exact bounded response
   consumption and original public request completion, require public zero
   active/preparing/pending requests, one connection and the exact inventory.
   Complete a second request on the same peer connection; require unchanged
   exact inventory and no extra accept or replay. This directly tests the
   candidate's TLS registration contribution without recovering private PIDs.
3. Command only the owned peer to close that idle connection, or use a separately
   specified public idle-expiry case. Under the original finite observation
   deadline require peer closure and public zero connections/resources. The
   source-bound registration/monitor/deletion path explains what that zero now
   proves; zero without the earlier inventory is insufficient. Add a separate
   retirement case requiring public durable await success and joined cleanup,
   with an independent live scope surviving exact body/completion checks.
4. Freeze every executable helper/peer and derive finite snapshot/helper/caller
   counts and owned-process joins. Record exact inputs, public receipts, peer
   events, counts and exit. Unsupported socket representations cannot be
   injected through a documented managed API: retain that branch as source-only
   coverage unless a legal public reproducer exists. A real failed-handshake
   case must preserve the candidate's conservative cleanup uncertainty rather
   than demanding fabricated termination evidence.
