## Proposed scoped design

Finite claim: **For a well-formed managed-H2 group staged/bind Session supplied to its actual continuation, a recognized terminal signal already pending when its group-specific mailbox check executes selects terminal cleanup, strips opening payload through the existing drop transformation, and cannot reach open or begin bind/notify-ready on that invocation.** With no recognized signal, the check returns the identical state and existing absolute-deadline/activation logic applies. Group/transport tokens, pins, original completion and service cleanup custody are preserved for the existing cleanup path.

This is a finite event-schema/state-transition claim. It is not a bound on mailbox size, selective-receive scan time, VM allocation, native memory, completion interiors or arbitrary future signals. A signal arriving after the check can still race with a subsequent open; do not claim a cross-process atomic cancellation barrier. Later live tests must qualify that race under the original completion cleanup rules.

Implement a small explicit group-only selective receive in Session, called by BOTH `handle_continue(:group_open, state)` after staged-shape validation and `handle_continue({:group_bind, upload}, state)` after bind-state/carrier/handle validation. It precedes recomputing/opening from original deadlines in the first callback and precedes the first owner bind in the second. Both continuations outrun ordinary mailbox delivery. Existing original-handle capture in group_open_result must stay before the bind continuation; queued termination at bind retains that exact request/original_request and runs existing cleanup/hold logic, even when owner completion is still nil. No original completion is newly published, fabricated or treated as successful cleanup by this slice. Use the existing event tuples/identity rules; no configurable callback, module replacement, mailbox traversal/flush, test activation switch, fake Fetch or new owner protocol. Take at most one recognized terminal event in mailbox matching order, with `after 0`; do not loop over arbitrary traffic. Recheck original absolute time immediately before the existing activation/open branch and never renew deadlines from now.

Recognized event family and behavior to freeze in the written design:

1. Existing public cancel/expire/consumed casts: terminate the unopened attempt; choose existing finite local cancellation/timeout reason and neutral pre-attempt health. For expire, total deadline reached means request_timeout, otherwise timeout. No ready/upload or replay follows.
2. Existing cleanup-cancel tuple only when its token matches and its deadline passes the same signed-time guard as the normal H2 handler. Preserve the supplied cleanup-request deadline for the existing cleanup clamp; discard the raw reason and do not lengthen original request/open deadlines.
3. Existing monitored DOWN only when BOTH monitor reference and stored PID match. Raw DOWN reason is not retained.
4. Existing opening_expired and total_expired atoms map respectively to timeout and request_timeout. This introduces no stronger authentication claim than the existing timer message protocol.

Unrelated messages, stale/wrong token/ref/PID, malformed H2 cleanup deadlines and fake payloads remain pending for ordinary handlers; they must not become terminal authority, be serialized into diagnostics, or be consumed by a broad catch-all receive. State already cancelled/consumed or deadlines already exhausted continue to fail through current local checks. On every terminal result reuse `drop_group_opening`/current local fail-settle behavior; do not zero counters or infer cleanup success. Pre-bind nil-completion uncertainty remains fail closed, even when no request was opened. Avoid extending this immediate package to pre-bind publication/custody redesign.

Minimal API choice for a testable actual production operation: add one `@doc false` internal Session helper `group_pending_control/1`, called by both actual `:group_open` and `{:group_bind, upload}` continuations. Proposed exact result: `{:ok, state}` on no recognized signal; `{:error, finite_reason, dropped_terminal_state}` on recognized terminal signal. It consumes only the listed mailbox control, sets cancellation/consumption/outcome and optional cleanup-request deadline, and preserves every other cleanup identity. It performs no owner call, await, Fetch, network or timer allocation. This is an internal implementation/test seam, not a public product interface or caller-supplied accounting flag. Keep its validation finite and source-specific; do not create a generalized mailbox/state-machine framework. A private helper plus equally direct callback tests is an acceptable smaller implementation if the author can prove the same behavior without fabricated ledger authority or broad test hooks.

Keep `ManagedH2GroupBoundary.activation/0` exactly `{:error,:accounting_not_ready}`. The future open branch remains dominated by BOTH this guard and existing activation. Do not change group Options, H2 owner prepare/launch admission, fixed reservation/projector, H1/H3/fixed endpoint behavior or dependencies. No new group reserve is adopted.
