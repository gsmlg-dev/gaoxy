## Design and assumptions

Observe only the original three OLD calls in active cycle1. Install read-only
Gaoxy Session debug hooks correlated by their original PID, token, monitors,
capture/source/child refs, public completion identity and actual peer stream.
Keep at most64 filtered events per original Session; routine polls do not
consume the observation budget. Emit14 phase snapshots around CAS, NEW seed,
the first two completions/source returns and the unchanged last-pending
assertion. Record original deadline scalars, clocks, completion result and
authentic G/T token/source/child presence. Never inspect private Fetch state,
consume the original monitors or mutate a runtime state to force reproduction.
Abrupt Session termination may omit its final scalar callback; that remains an
explicit observation limitation, not permission to infer a cause.

For idle cycle3, emit the actual G snapshot already obtained by the test and a
separate Store observation immediately before the unchanged NEW-only assertion,
with both original hold starts. Snapshots from different owners are sequential,
not an atomic global snapshot. In particular, an OLD baseline pin in G with no
tokens/probes is evidence of the pending-release phase even if Store settles
between the two observations. No settling wait or other repair is included.

Every original assertion, operation order, response, timeout, cap and teardown
remains. Hooks are removed in `after` and registered for failure cleanup; the
original failing assertion remains authoritative. Observation timing can alter
a race, so a diagnostic nonreproduction does not prove a repair or stability.

## Execution and checks

1. Archive the proposal and exact diff; root formats the source as preparation
   with its own actual exit/log/hash receipt. Freeze the formatted source,
   complete unchanged source map, current documents and exact diagnostic argv.
2. Independent SPEC then CODE review must resolve actionable findings before
   root executes. Their acceptance is limited to the diagnostic source/plan.
3. Run separately selected nativeH1→h2c active and idle cells, loading both the
   defining fixed fixture and full group file. Use ExUnit's `--only test:` name
   filter, with the literal generated full test name in one argv argument.
   The frozen JSON records each exact outer/payload argv. Check the actual test
   and exclusion counts; the prior104 total predicts1 executed/103 excluded per
   cell but does not establish that outcome. If selection is wrong, classify
   the diagnostic as invalid and correct selection; never claim it as a gate.
4. Use the existing command collector with `--kind static` solely to preserve
   exact payload exit, counts (including exclusions), source-before/after,
   finite600s command bound, genuine adopted waits and joined process custody.
   This does not turn the ExUnit diagnostic into a static check or a passing
   acceptance run. A reproduced assertion failure remains FAIL in its receipt.
5. Audit safe structured observation rows, classify actual initiating events
   and snapshot timing, then propose the smallest causal repair. Preserve
   UNKNOWN if evidence is incomplete. All complete unfiltered eight-profile
   qualification and subsequent prescribed gates remain required.

No deployment, publication, dependency edits, private-client inspection,
