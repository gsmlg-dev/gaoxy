# Gaoxy v0.4.0

Release candidate; portable qualification and GitHub publication are pending.

v0.4.0 adds native server WebSocket over HTTP/2, explicit prior-knowledge h2c and
HTTP/3 using RFC 8441/9220 extended CONNECT. Embedded HTTP/Phoenix HTTPS defaults
to H2 then H1, retaining H1 fallback. Plain HTTP remains H1 unless h2c is selected
explicitly. WebSocket extended CONNECT remains a separate listener opt-in;
Phoenix additionally lists exact WebSocket paths and preserves its existing
Origin/session/CSRF/authentication checks. Channels and LiveView mount, updates
and upload passed actual H2/H3 and H1 browser qualification.

This release also contains the accepted M3 managed H1 connection reuse and
managed H2/h2c fixed/group upstreams, probes, Generation ownership and bounded
resource accounting, using public HTTPFetch 0.21.10 APIs. These are embedded
configuration capabilities. Standalone JSON retains H1 defaults, explicit
downstream H2/h2c/H3 and fixed H1/H3 origins; it does not activate managed
upstream handles/groups/probes or WebSocket endpoints.

M5 source acceptance passed 136 scoped tests/0 failures, H2/h2c/H3 independent
peers each 15/15 and Phoenix H2/H3/H1 browser profiles each 12/12, with independent
SPEC/CODE review. M3 ordinary merge verification passed 62 executed cases/0
failures. These implementation receipts are separate from portable artifact
qualification, whose actual results will be recorded before publication.

Clients choose actual WebSocket transport. H3 browser acceptance used controlled
QUIC-first selection; automatic H3 selection with TCP available is unqualified.
The multiplexed browser profiles' rejected-Origin checks returned H1 TLS403.
Outbound H2/H3 WebSocket proxying, compression, generic H2/H3 CONNECT, WebTransport,
DATAGRAM and the remaining recorded H3 limitations are outside this release.
Specialist abnormal/disconnect, slow-peer, pressure and sustained-load testing
remains assigned to its dedicated environment.

The selected downloadable platform is Debian bookworm/glibc Linux x86_64. New
hosted CI is NOT RUN: release pushes skip the automatic mixed/soak jobs to retain
the ordinary-only scope. Historical BLOCKED_ENV jobs remain separate. No
deployment, production operation, Hex/OCI publishing or release-artifact E2E
workflow activation follows.
