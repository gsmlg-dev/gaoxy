# Gaoxy v0.5.0

Release preparation: 2026-10-20, Asia/Shanghai. **Publication: NOT RUN.**

Gaoxy v0.5.0 replaces Thousand Island with
[Hell](https://github.com/gsmlg-dev/hell) 0.1.2 for TCP/OTP TLS, using the public
`Hell` namespace and OTP application `:hell`. Hell is pinned to Git revision
`59eed42b019ca41413d1b8cd7a7dc3e344bb93ee`. Accepted protocol and Phoenix
functionality and the HTTP/QUIC dependency cohort are unchanged. Published
v0.4.0 source and binaries retain Thousand Island; their evidence does not
qualify the v0.5.0 artifact.

Retained functionality includes native H1/H2/h2c/H3 HTTP, downstream RFC 8441/9220
WebSocket and Phoenix integration, embedded managed H1 reuse and managed H2/h2c
fixed/group upstreams, probes and Generation/resource accounting. Embedded
HTTPS prefers H2 with H1 fallback; plain TCP defaults to H1, h2c is explicit,
and extended CONNECT needs listener opt-in and exact Phoenix WebSocket paths.

Standalone JSON defaults HTTP services to H1 and permits explicit H2/h2c or a
separate H3 HTTP service, with fixed H1/H3 origins. JSON does not activate
managed upstream handles/groups/probes or WebSocket endpoints. Packaged
WebSocket verification uses the public embedded API. Clients choose their
actual WebSocket transport: retained browser H3 evidence uses controlled
QUIC-first selection, and automatic H3 selection with TCP available remains
unqualified. The recorded rejected-Origin 403 used H1 TLS.

WebTransport, DATAGRAM and the existing H3 limitations remain outside this
release. Specialist abnormal/disconnect, slow-peer, pressure, load and soak
qualification remains excluded and assigned to its dedicated environment;
historical failures, blocked/unexecuted results and assertions are preserved.

production data/certificates, Vault and public management changes remain
outside this release.
