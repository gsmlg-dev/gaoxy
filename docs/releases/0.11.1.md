# Gaoxy 0.11.1

Fix HTTP/1 peer-close polling at the inclusive `max_buffer_bytes` boundary
([#11](https://github.com/gsmlg-dev/gaoxy/issues/11)). A full buffer remains
usable for the next keep-alive request. Polling can still observe pending input
or peer closure; an actual excess byte produces `:buffer_limit` without growing
the retained input buffer beyond its limit.

Callers must retain the returned `Plug.Conn` after every poll and abort it on
errors. The excess observation consumes one byte, so `:buffer_limit` is terminal.
No extra application buffer margin is required. Finite I/O, request and shutdown limits,
service resource accounting and HTTP/2 stream isolation remain in force.

All six Hex distributions and the standalone application advance to `0.11.1`.
Dependency versions and vendored upstream provenance are unchanged. This patch
adds no deployment or specialist load/pressure qualification.
