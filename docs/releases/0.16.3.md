# Gaoxy 0.16.3

- HTTP/2: stream resets that a peer provokes on a live stream (DATA or HEADERS
  after END_STREAM, an invalid stream WINDOW_UPDATE, a body that contradicts
  its declared length) now count against `control_rate`, like the control
  frames the peer sends itself. Exceeding it ends the connection with GOAWAY
  `ENHANCE_YOUR_CALM`. Before, each such cycle cost a worker start and kill
  without limit. Frames for a stream the server already finished are not counted.
- HTTP/2: the partial-frame timer bounds one pending frame or header block and
  is cleared when it completes. A connection whose socket deliveries kept ending
  mid-frame was closed with `PROTOCOL_ERROR` after one `frame_timeout` even
  though every frame arrived promptly.
- HTTP/1.1: status codes without a registered reason phrase (for example 499,
  520–530 and 599) are sent with an empty phrase. Before, the connection was
  closed without a response; HTTP/2 and HTTP/3 already relayed them.
- Forward proxy: `Gaoxy.Proxy.ForwardHTTP` no longer adds `X-Forwarded-For`,
  `X-Forwarded-Host` or `X-Forwarded-Proto` to forwarded requests, so a
  destination does not learn the client address. Inbound forwarding fields are
  still removed. Reverse proxying is unchanged.
- Admission: while a resource-budget operation is pending, at most one delayed
  retry of terminal leases, spawns and cleanups is outstanding. Before, every
  waiting entry scheduled its own full retry, and retries multiplied for as long
  as the budget authority was slow.

No configuration or dependency changes. `docs/acceptance/` is no longer part of
the repository.
