# Gaoxy 0.12.2

An HTTP/1 peer that disconnects after sending request headers can now close
normally while Gaoxy creates the request exchange. Previously, a failed socket
identity lookup could raise `MatchError`, including for cancelled uploads with
`request_timeout: :infinity`.

Expected closed-socket errors stop the connection before application dispatch.
Admission ownership and retained bytes are released when the owner exits;
unexpected transport errors retain their error disposition. Successful request
metadata and finite/infinite request deadlines keep their existing behavior.

The regression coverage includes controlled peer/local identity failures and
synchronized real TCP resets, followed by healthy sibling and new requests.
All six Hex distributions and the standalone application advance together to
`0.12.2`. Dependency requirements and pins are unchanged.
