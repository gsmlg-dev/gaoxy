# Gaoxy 0.16.0

Gaoxy upgrades its HTTP, TLS, QUIC and transport dependencies to the coordinated
Hex `1.0.0-rc.14` releases (the 1.0 API freeze) and requires `~> 1.0.0-rc.14`.
This release contains breaking changes for TLS listeners.

## Breaking changes

- Hell TLS listeners run on the ex_ssl server engine, which supports TLS 1.3 only
  and requires OTP 28+. TLS listener `versions` must be `[:"tlsv1.3"]` (the
  default); `[:"tlsv1.2"]` and `[:"tlsv1.3", :"tlsv1.2"]` are rejected before
  binding with `:invalid_tls_versions`. OTP-only `:ssl` server options are
  rejected by the engine. Upstream proxy clients keep explicit bounded TLS 1.2.
- Managed HTTP/2 upstreams inherit http_fetch's RFC 9113 §8.7 replay: a
  non-streamed request the upstream did not process (above a GOAWAY
  last-stream-id or refused) is re-sent on another connection within the same
  deadline instead of failing with 502. If no connection answers in time, the
  client sees 504. An opt-out is requested upstream
  ([gsmlg-dev/http_fetch#167](https://github.com/gsmlg-dev/http_fetch/issues/167)).
- A TLS peer that half-closes without `close_notify` is reported as
  `:econnreset` after buffered input is drained (OTP 28 TLS 1.3
  `:ssl.shutdown(socket, :write)` sends none); a `close_notify` still ends in
  `:closed`.
- The HTTP/TLS/QUIC, Abyss and Hell requirements are raised from
  `~> 1.0.0-rc.4` to `~> 1.0.0-rc.14`; consumers must update the whole cohort.

## Fixes

- [#25](https://github.com/gsmlg-dev/gaoxy/issues/25): pin the four external
  bitstring-size variables in WebSocket encoding/decoding, removing Elixir 1.20
  compiler warnings while preserving Elixir 1.18 compatibility.
- [#26](https://github.com/gsmlg-dev/gaoxy/issues/26): reserve bounded accounting
  windows during native H1 Plug request-body reads. A 5 MiB body uses 28
  synchronous admission calls in the regression cases, including 1 KiB reads
  and chunked framing, instead of thousands of calls. Byte limits, absolute
  deadlines and exact accounting after each Plug read remain enforced.
  Optional headroom falls back to exact accounting under tight budgets or
  memory pressure; reserved headroom stays charged as temporary memory.
  H2/H3 and non-Plug body accounting retain their existing behavior; no timeout
  changes are required.

## Dependency migration

[#27](https://github.com/gsmlg-dev/gaoxy/issues/27): migrate to the rc.14 API freeze.

- Proxy HTTP clients and WebSocket sessions no longer pass the removed
  `tls_backend` option; ex_ssl is the only TLS engine.
- Managed HTTP/2 response validation and the HTTP fetch client read a streamed
  response's pid from `HTTP.Response.body`, matching the rc.14 struct without the
  `stream` and `body_used` fields, with unchanged strict shape and size checks.
- Managed HTTP/2 request handles accept the rc.12 `HTTP.Promise` `callbacks`
  field only as an empty list; without this every managed H2 request was rejected.
- The UDP datagram bridge uses `Abyss.Endpoint` with `datagram_handler:` instead
  of the deprecated `Abyss.Handler` mode.
- rc.14 includes the ex_ssl server fix for buffered plaintext after a peer
  `close_notify` ([gsmlg-dev/http_fetch#163](https://github.com/gsmlg-dev/http_fetch/issues/163)),
  which truncated TLS H1 input under rc.12/rc.13.
- Use `~> major.minor` requirements in active manifests and published sibling
  packages. Lockfiles retain exact resolved versions.
