# Gaoxy 0.7.0

Native HTTP/1.1 and cleartext HTTP/2 prior knowledge can now share one TCP
listener. Embedded endpoints, Plug, standalone routes and Phoenix HTTP options
all use the same connection-level selection:

```elixir
transport: :tcp,
protocols: [:http2, :http1],
h2c: :prior_knowledge
```

Standalone JSON uses `"protocols": ["http2", "http1"]` and
`"h2c": "prior_knowledge"`. Plain TCP defaults to H1-only and TLS retains
existing ALPN behavior. This enables prior knowledge; HTTP/1.1 Upgrade is not
implemented by this change.

Detection compares the complete 24-byte H2 preface and preserves fragmented,
coalesced, body and pipelined bytes. It retains at most 23 undecided bytes,
reuses one owner admission lease, and fixes first-request/startup deadlines at
the original first byte. Protocol selection never falls back after a parser
error. An absolute startup deadline also prevents a queued timeout from losing
to a late SETTINGS acknowledgment.

The coordinated five Hex distributions and standalone application retain the
existing dependency cohort and publication process. The release smoke now
tests explicit H1 and independent H2 clients simultaneously on the mixed port,
alongside the existing dedicated proxy and transport checks.

The [acceptance record](../acceptance/mixed-h2c.md) contains commands, exact
counts, source identities and independent review. Publication receipts will be
recorded there after publication. It also
preserves an unrelated existing H1 upload failure with a 4096-byte service
budget, reproduced on the baseline; that body-copy reservation case is
unchanged. Specialist exceptional/pressure/soak qualification and deployment
remain outside this release.
