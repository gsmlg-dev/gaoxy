# Gaoxy 0.14.1

HTTP/1 connection polling now retains bounded input batches instead of requiring
one public poll and synchronous admission cycle per byte. This fixes the overhead
reported in [#19](https://github.com/gsmlg-dev/gaoxy/issues/19) when streaming
handlers drain pipelined input to observe peer closure.

Each batch is bounded by 8 KiB, `max_read_chunk`, remaining input-buffer capacity
and resource admission. Short available input returns without waiting for a full
batch. Low byte credit reduces the admitted batch before any input is consumed.

The inclusive `max_buffer_bytes` boundary remains valid: a full buffer can be idle
or closed, and only an observed excess byte rejects it. Polling preserves received
content through EOF, the original request deadline and resource accounting.
