# Gaoxy 0.14.0

Gaoxy uses adaptive memory admission shared across instances in one BEAM VM.
HTTP/HTTPS/H3 listeners, ListenerSets and Phoenix Endpoints share that capacity
pool. Separate operating-system processes require operator capacity partitioning.

The default soft budget is 50% of effective physical/container memory capacity;
the hard threshold is twice the soft budget. Unreliable detection falls back to
256 MiB soft and 512 MiB hard. Usage at or below soft is normal. Above soft
through hard, admission continues with rate-limited warnings. A new allocation
or growth projected above hard is refused. Existing work can complete within
its committed resources, and released capacity becomes available immediately.
Protocol, allocation and system-memory safety guards remain independently active.

Accounting follows retained memory and temporary obligations through connection,
request, stream, output and cleanup lifetimes. Idle connections avoid unnecessary
worst-case reservations; H2 decoder peaks remain guarded before expansion.
Request completion or WebSocket upgrade ends ordinary request membership, while
connections, streams and buffered output retain their own lifetimes. Worker
death alone does not release resources whose cleanup is still unconfirmed.

Service concurrency now has distinct `max_connections`, `max_requests` and
`max_streams` quotas, defaulting to 16,384 connections, 65,536 ordinary requests
and 65,536 H2/H3 request streams; lower protocol ceilings still apply. Omitted
historical aggregate lease and byte caps give way to adaptive accounting.
Explicit `max_active` retains its legacy ordinary-lease cap, including connection,
writer and worker leases. Explicit `max_bytes` retains its transport/cleanup byte
cap, excluding WebSocket retention. Values equal to historical defaults still
count as explicit policies.

Set an optional instance `resource_budget` with both `soft_limit` and
`hard_limit` to choose finite thresholds; an explicit hard limit is never
doubled. ListenerSet, Gateway, Phoenix Endpoint and standalone JSON configuration
carry this policy. Explicit instance policies still share the VM pool.

Raw TCP/TLS handlers prepay bounded I/O credit so admitted connections can still
reply during drain. Defaults require 905,139 bytes per connection; smaller
explicit byte caps must be migrated. Raw socket buffers default to 2,048 bytes,
and larger explicit settings increase the reserved floor.
Retained handler state and sent output detach small slices from larger binary
backing, preserving state values and resource handles within the same VM.

Use `Gaoxy.resource_budget(instance)` to inspect capacity, thresholds, retained
and temporary usage, active connections/requests/streams, state, detection,
rejections and VM totals. Snapshot, state, rejection and fallback telemetry
support monitoring. Unavailable inspection must not be treated as zero usage;
accounted usage is not total BEAM RSS or kernel socket memory.

See the [resource-budget guide](../resource-budget.md) for configuration,
migration, accounting boundaries and observability.
